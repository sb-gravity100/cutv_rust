# FILE_INDEX.md

File system index with tags and one-line descriptions. Update whenever files are added, moved, or removed.

## Root

- `Cargo.toml` — `[build]` crate manifest, dependencies (eframe/egui, gstreamer/gstreamer-app/gstreamer-video, ffmpeg-next, gifski, rfd, chrono, anyhow, log, env_logger), `[build-dependencies]` (`winres`, embeds the `.exe` icon — see `build.rs`). `rodio` is also listed but unused — vestigial from the pre-GStreamer audio-player era (see `player.rs`'s doc comment), predates and is untouched by the ffmpeg-next work.
- `Cargo.lock` — `[build]` pinned dependency versions.
- `build.rs` — `[build]` embeds `assets/icon.ico` as a Windows PE resource via `winres`, so the compiled `.exe` itself carries the icon (Explorer, taskbar-before-launch, context-menu default icon) — separate from the runtime window/taskbar icon `main.rs` sets via `eframe::icon_data`.
- `assets/icon.ico`, `assets/icon-256.png` — `[assets]` app icon (dark rounded-square badge, white play triangle, green/red IN/OUT brackets matching `app.rs`'s own timeline marker colors). Generated via a throwaway Pillow script, not part of the build pipeline itself — regenerate by hand if it ever needs to change.
- `.cargo/config.toml` — `[build]` sets `PKG_CONFIG_PATH`/`PKG_CONFIG` so `gstreamer-rs`'s and `ffmpeg-sys-next`'s sys crates find vcpkg's GStreamer/FFmpeg automatically (same `lib/pkgconfig` dir has both). See `PLAN.md` for the vcpkg setup this depends on (and the `GST_PLUGIN_PATH`/`PATH` runtime env vars, set separately as persistent user env vars, not via this file).
- `vcpkg-overlay/gstreamer/` — `[build]` vcpkg overlay port: copy of upstream `gstreamer` with `-Dorc=enabled` + pre-vendors ORC 0.4.42 into `subprojects/orc` (upstream disables ORC — GStreamer's SIMD codegen lib — because vcpkg has no port for it under that name; see PLAN.md's "low-FPS investigation"). Passed via `vcpkg install --overlay-ports=vcpkg-overlay ...`.
- `CLAUDE.md` — `[docs]` session rules + project architecture guidance for Claude Code.
- `.gitignore` — `[build]` ignores `/target`.

## `src/`

- `main.rs` — `[entry]` `#![windows_subsystem = "windows"]` (no console window on a standalone launch — double-click, context menu, drag-onto-exe; launching from an existing terminal still inherits its stdout/stderr for logging). Resolves target video path, probes it, sizes the window, loads `assets/icon-256.png` as the runtime window/taskbar icon, launches `eframe` with `app::CutvApp`.
- `app.rs` — `[ui][state]` `CutvApp` (`eframe::App` impl) — owns all playback/UI state, egui drawing (video frame, timeline, transport, edit row, status bar, FPS counter, crop overlay), keyboard shortcuts, `do_cut()`/`do_gif()` export (both bake in a crop filter whenever a crop is set, plus a speed-change filter whenever `speed != 1.0`, and share the `cut_progress_shared` progress-bar field since only one export runs at a time — `do_cut` drives `export::cut_video`, `do_gif` drives `gif::spawn_gif_export`, both in-process via `ffmpeg-next` as of Phase 10). As of Phase 11, GIF is the default/primary export (prominent button, `Enter`/`G`); video-format cut is secondary (dim `MP4` button, `V`). `open_video()`/`load_video()` (native file picker via `rfd`, or drag-and-drop a file onto the window — both funnel into `load_video()`, which re-initializes the whole app in place, same as `new()`, for opening a different video mid-session without relaunching); a full-window overlay (egui `Order::Foreground` layer) gives live feedback while a file is being dragged over the window. Constructs `Player` directly (no native window handle needed — frames render as an egui texture). `speed`/`keep_pitch` fields (edit row's `{speed}×` button opens a popup: log slider 0.1x-10x + "Keep pitch" checkbox) drive both live preview (`Player::set_speed`/`set_keep_pitch`) and the export filters.
- `export.rs` — `[ffmpeg-next][export]` `cut_video()` — `do_cut`'s final trim+encode, in-process via the `ffmpeg-next` crate (libavformat/libavcodec/libavfilter bindings) instead of spawning an `ffmpeg` CLI subprocess. Demux → decode → filter (crop/setpts/atempo/asetrate via an `ffmpeg::filter::Graph` built from filter-spec strings, same pattern the old CLI path's `-vf`/`-af` used, including `probe::atempo_chain()`'s audio chain) → encode (NVENC/CPU codec-family matching ported from the now-removed CLI-era `probe::encode_args`, rebuilt against `ffmpeg-next`'s `Dictionary`-option API) → mux, with a manual packet/frame send/receive loop and `pkt.rescale_ts` between decoder/encoder/muxer time bases (from the *encoder's own* time_base, not the input stream's — see `PLAN.md`'s "The ffmpeg-next export path" for a real bug this distinction caused on WebM sources). See that same section for why this doesn't repeat the earlier hand-rolled `ffmpeg-next` *decoder*'s problems (Approach 3), for four more real bugs found/fixed during verification (a segfault, an AAC frame-size violation, unregistered CPU codecs needing a vcpkg FFmpeg rebuild, a filter-graph time_base mismatch), and for the Phase 10 subsection covering the same treatment applied to `probe.rs`/`proxy.rs`/`thumbs.rs`/`gif.rs` — none of those still shell out to `ffmpeg`/`ffprobe`; nothing in the app does anymore.
- `crop.rs` — `[feature]` resizable/movable crop rectangle (`CropRect`, source-pixel coords) drawn directly over the video texture in egui; `to_canvas`/`canvas_to_source_delta` for coordinate mapping, `hit_test`/`apply_drag` for the 8 resize handles + move-by-drag-inside, `to_vf()` for the ffmpeg `-vf crop=...` string (reused as a libavfilter graph-string fragment by `export.rs`, not just the CLI path). `app.rs`'s `ui_crop_overlay` drives it.
- `gif.rs` — `[feature]` `spawn_gif_export` — GIF export via `gifski`: the IN→OUT range is decoded/filtered from the **original source** in-process via `ffmpeg-next` (crop/setpts/scale/fps filter graph, same shape `export.rs`'s video pipe uses, plus a trailing `format=rgba` stage gifski needs — Phase 10, previously a spawned `ffmpeg` subprocess piping raw RGBA frames over stdout), fed to a `gifski::Collector`/`Writer` pair on two threads (required by gifski's own blocking-queue contract). Respects `crop_rect` and `speed`, and reports progress through the same `Arc<Mutex<f32>>` `do_cut` uses. See `PLAN.md`'s "GIF export design".
- `player.rs` — `[playback]` `Player` — wraps a GStreamer `playbin` pipeline (`play`/`pause`/`seek`/`step_frames`/`set_mute`/`set_speed`/`set_keep_pitch`/`poll`/`is_seeking`). Every seek is frame-exact (`SeekFlags::ACCURATE`) — no `seek_fast`/keyframe-snap variant; see PLAN.md's "The scrub proxy" for why that tradeoff isn't needed. `set_speed`/`set_keep_pitch` drive live preview's variable-speed playback (rate-seek + playbin's `audio-filter` slot, `scaletempo`/`identity`) — see PLAN.md's "Variable speed"/Phase 8. Video frames pulled from an `appsink` (via a GPU `d3d11upload!d3d11convert!...` colorspace-conversion bin, falling back to CPU `videoconvert`) as raw RGB for the caller to upload as a texture — `poll()` tries both `try_pull_preroll()` and `try_pull_sample()` since appsink delivers frames differently depending on pipeline state (paused vs playing). `max-buffers=1 drop=true` on the appsink caps it to the newest frame — needed once variable-speed playback could push frames faster than the UI drains them. Audio is playbin's own default sink — no separate audio code. Has detailed `trace!`/`debug!` timing instrumentation (see PLAN.md's "low-FPS investigation") — `RUST_LOG=trace` for per-frame numbers.
- `proxy.rs` — `[playback][ffmpeg-next]` `spawn_proxy` — background-thread in-process transcode (`ffmpeg-next`, Phase 10; previously a spawned `ffmpeg` subprocess) of the source into a short-GOP (`gop=8`/`keyint_min=8`/`sc_threshold=0`) scrub proxy, NVENC first with a libx264 `ultrafast` fallback; audio always re-encoded to AAC 160k. Structurally a simplified `export.rs` (no crop/speed/trim — full-duration passthrough-resolution transcode with fixed encoder settings), reusing the same bug-avoidance patterns (`aformat`+`asetnsamples` for the audio pipeline, `encoder.time_base()` for `pkt.rescale_ts`, `stream.time_base()` for the filter graph's `time_base=` arg) `export.rs`'s verification found necessary. `app.rs` swaps `Player` over to it once ready, preserving position/play state; `do_cut()`/`export::cut_video` always use the original file regardless. See PLAN.md's "The scrub proxy" and "The ffmpeg-next export path"'s Phase 10 subsection. Proxy files are named `cutv_proxy_<content-hash>.mp4` (`video_cache_key`, a bounded head/tail sample + length hash, not a full-file hash) so re-opening the same video content (even under a different filename) reuses an existing proxy instead of re-transcoding — including one left over from a crashed previous session. `cleanup_all_proxies()` sweeps every `cutv_proxy_*` temp file on normal app exit (`CutvApp`'s `Drop` in `app.rs`); nothing deletes them mid-session. See PLAN.md's "Proxy caching and cleanup".
- `thumbs.rs` — `[playback][thumbnails][ffmpeg-next]` `spawn_thumbs` — background-thread in-process single-frame grabs (Phase 10; previously a spawned `ffmpeg` process per thumbnail) for the timeline thumbnail strip (N=24 at 72×44), independent of `Player`. Seeks + decodes forward to each target timestamp, then resizes via `software::scaling::Context` (swscale) directly — a plain resize+format-convert has no need for the text filter-graph machinery `export.rs`/`gif.rs` use.
- `probe.rs` — `[ffmpeg-next][metadata]` `probe_video` (in-process `format::input` + stream inspection for duration/fps/width/height, Phase 10 — previously parsed `ffprobe`'s JSON output), `nvenc_available()` (cached in-process `ffmpeg_next::encoder::find_by_name("h264_nvenc")` check, Phase 10 — previously shelled `ffmpeg -encoders` and grepped its stdout; used by `export.rs`'s and `proxy.rs`'s encoder selection), `atempo_chain` (pitch-preserving speed-change filter-spec string, reused as-is by `export.rs`/`proxy.rs`). The CLI-arg-string `encode_args`/`has_audio_stream`/`audio_sample_rate`/`normalized_audio_codec` this used to also hold were removed once `do_cut` stopped needing them (Phase 9; see `export.rs`, which reimplements the same codec-selection logic against `ffmpeg-next`'s option API instead).
- `util.rs` — `[helpers]` `fmt_tc` (timecode string), `fmt_speed` (speed-multiplier display string). `parse_fps` (used to parse ffprobe's `"num/den"` frame rate strings) was removed as dead code once `probe_video`'s Phase 10 port stopped needing it.

- `bin/mpv_spike.rs` — `[spike][reference, no longer the playback direction]` Phase 0 proof that libmpv can render into a native Win32 child window embedded in an app window. Not wired into `main.rs`. Kept only as a reference for the win32-embedding/runtime-DLL-loading technique, in case it's ever needed again — playback is GStreamer now, not mpv.
